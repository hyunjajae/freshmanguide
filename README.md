# 팀빌딩 접수 사이트 v2

오프라인 행사 현장에서 **접수처는 참가자를 접수하고, 진행 FG는 그 현황을 실시간으로 확인**하는 웹앱입니다.

- 참가자 1,600명 / 3일 / LC 93개 규모를 기준으로 만들었습니다.
- 접수처에서 [접수]를 누르면 FG 화면에 **즉시** 반영됩니다. (새로고침 필요 없음)

## 1. 처음 세팅하기

### 1-1. Supabase 프로젝트 만들기

> Supabase = 데이터를 저장하는 무료 데이터베이스 서비스입니다. 예전의 구글 스프레드시트 자리를 대신합니다.

1. [supabase.com](https://supabase.com) 접속 → **Start your project**
2. **⚠️ 반드시 학생회 공용 구글 계정으로 가입하세요.** 개인 계정으로 만들면 내년 회장이 못 씁니다.
3. **New project** 클릭
   - Name: `teambuilding-2026` (아무거나 괜찮습니다)
   - Database Password: 아무거나 만들고 **어딘가에 적어두세요**
   - Region: `Northeast Asia (Seoul)` 를 고르면 가장 빠릅니다
4. 프로젝트 생성까지 2분 정도 걸립니다.

### 1-2. 데이터베이스 만들기

1. 왼쪽 메뉴에서 **SQL Editor** 클릭 → **New query**
2. 이 폴더의 `supabase/schema.sql` 파일을 열어서 **전체 복사**
3. 붙여넣고 오른쪽 아래 **Run** 클릭
4. `Success. No rows returned` 가 나오면 성공입니다.

### 1-3. 연결 정보 넣기

1. Supabase 왼쪽 메뉴 → **Project Settings**(톱니바퀴) → **API**
2. 두 가지를 복사합니다.
   - **Project URL** (예: `https://abcdefg.supabase.co`)
   - **Project API keys** 의 **`anon` `public`** 키 (긴 문자열)
3. 이 폴더의 `.env.example` 파일을 복사해서 이름을 **`.env.local`** 로 바꿉니다.
4. 파일을 열어 값을 채웁니다.

```
VITE_SUPABASE_URL=https://abcdefg.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi... (복사한 anon 키)
```

> `anon` 키는 공개되어도 괜찮은 키입니다. 브라우저에 들어가는 게 정상이고,
> 실제 데이터는 데이터베이스 쪽에서 막아두었습니다. (`service_role` 키는 **절대** 넣지 마세요)

### 1-4. 실행하기

터미널(명령 프롬프트)을 이 폴더에서 열고:

```bash
npm install
```

```bash
npm run dev
```

브라우저에서 http://localhost:5680 접속 → 화면이 뜨면 성공입니다.

### 1-5. 관리자 비밀번호 바꾸기 (필수)

처음에는 아래 계정이 만들어져 있습니다.

| 아이디 | 비밀번호 |
| --- | --- |
| `admin` | `changeme1234` |

**접수처로 로그인 → ⚙️ 명단 관리 → 계정 탭** 에서 같은 아이디(`admin`)로 새 비밀번호를 저장하면 덮어써집니다.
반드시 바꾸고 시작하세요.

## 2. 행사 준비 순서

### ① 참가자 명단 넣기

1. 구글폼 응답 스프레드시트를 엽니다.
2. **파일 → 다운로드 → 쉼표로 구분된 값(.csv)** 으로 받습니다.
   *(또는 시트에서 전체 선택 후 Ctrl+C 해서 붙여넣어도 됩니다)*
3. 사이트에서 **접수처 로그인 → ⚙️ → 참가자 명단** 탭
4. CSV 파일을 끌어다 놓습니다.
5. **열 이름이 자동으로 인식됩니다.** (성함/이름 → 이름, 학번 → 학번, 휴대폰/연락처 → 연락처 …)
   틀렸으면 직접 골라주면 됩니다.

   | 항목 | 필수 | 비고 |
   | --- | --- | --- |
   | 이름 | ✅ | |
   | LC 번호 | ✅ | |
   | 학번 | | 있으면 FG가 현장에서 확인할 수 있고, 중복 검사에도 쓰입니다 |
   | 연락처 | | |
   | 계열 | | |
6. 검사 결과가 나옵니다.

| 분류 | 뜻 | 처리 |
| --- | --- | --- |
| **정상** | 문제 없음 | 그대로 업로드 |
| **자동 제거** | 이름·연락처·LC·계열이 **전부** 같은 완전 중복 | 물어보지 않고 하나만 남김 |
| **확인 필요** | 학번 중복 / 연락처 중복 / 이름+LC+계열 중복 / 연락처 형식 오류 / LC 범위 밖 | 체크를 풀면 제외됨 |
| **빨간 줄** | 이름이나 LC가 없어서 넣을 수 없음 | 자동으로 제외 |

7. **전체 교체** 를 고르고 `전체교체` 라고 입력한 뒤 업로드합니다.

> ⚠️ **행사 당일에는 절대 '전체 교체'를 쓰지 마세요.** 접수 기록까지 전부 사라집니다.
> 당일에 사람을 추가해야 하면 접수 화면의 **➕ 현장 등록** 을 쓰세요.

### ② FG 계정 넣기

**⚙️ → 계정 → FG 일괄 등록** 탭에서 아래 형식으로 붙여넣습니다.

```
성함	학번	담당LC
홍길동	20240001	1,2
김철수	20240002	3
```

- 담당 LC는 한 칸에 `1,2,3` 이라고 써도 되고, 칸을 나눠 써도 됩니다.
- FG는 **성함 + 학번(10자리)** 으로 로그인합니다.
- 담당 LC가 없는 계정은 목록에 빨간색으로 표시되니 꼭 확인하세요.

### ③ 설정 확인

**⚙️ → 설정** 에서 행사 이름과 **하루 LC 개수 / 총 일수**를 확인합니다.
기본값은 `31개 × 3일 = LC 93개` 이고, 여기서 바꾸면 코드 수정 없이 바로 적용됩니다.

### ④ 배포하기 (다른 사람도 쓸 수 있게)

`npm run dev` 는 내 컴퓨터에서만 열립니다. FG들이 각자 폰으로 접속하려면 인터넷에 올려야 합니다.

**가장 쉬운 방법 — Vercel**

1. 이 폴더를 GitHub에 올립니다. (`.env.local` 은 `.gitignore` 에 있어서 올라가지 않습니다)
2. [vercel.com](https://vercel.com) 에 GitHub 계정으로 로그인 → **Add New Project** → 저장소 선택
3. **Environment Variables** 에 두 개를 넣습니다.
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
4. **Deploy** → 주소가 나오면 그걸 FG들에게 공유하면 됩니다.

> 행사 **최소 하루 전**에 배포하고, 실제 폰으로 로그인까지 해보세요.

## 3. 화면별 기능

### 📍 접수처 (관리자)

| 기능 | 설명 |
| --- | --- |
| **검색** | 이름 전체/일부, **초성**(`ㄱㅎㄱ` → 김현규), **연락처 뒷자리**(숫자 3자 이상), LC 번호로 좁히기 |
| **접수** | 누르는 즉시 처리. 동명이인은 **연락처 전체**가 보여서 구분됩니다 |
| **Enter 단축키** | 검색 결과에 미접수자가 **정확히 1명**이면 Enter만 눌러도 접수됩니다 |
| **접수 취소** | 잘못 눌렀을 때 되돌리기 (확인창 뜸) |
| **➕ 현장 등록** | 명단에 없는 사람을 즉석에서 추가 + 바로 접수. '현장' 표시가 붙습니다 |
| **📋 미접수자** | 아직 안 온 사람 목록. 일차/LC로 거르고 **복사**하거나 **CSV로 저장** |
| **📊 통계** | 전체·일차별·LC별 접수율. 15초마다 자동 갱신 |

### 🚶 진행 FG (조회 전용)

- 로그인하면 **본인 담당 LC의 명단만** 보입니다.
- 담당 LC가 한 일차에만 있으면 날짜 선택을 건너뜁니다.
- **⏳미접수 / ✅접수 완료** 로 나뉘고, 완료된 사람은 **최근 접수순**으로 위에 쌓입니다.
- 접수처에서 누르는 순간 **바로 반영**됩니다.
- 명단 보는 동안 **화면이 자동으로 꺼지지 않습니다**.
- 본인 담당 LC 인원에 한해 **연락처와 학번을 전부** 볼 수 있습니다.
  (담당하지 않는 LC의 데이터는 서버에서 아예 내려보내지 않습니다)

### 공통

- 새로고침하거나 다른 앱 갔다 와도 **로그인이 유지**됩니다 (18시간).
- 인터넷이 끊기면 화면 위에 빨간 띠가 뜨고, 연결되면 **자동으로 다시 맞춥니다**.
- 접수 버튼은 누르는 즉시 반응하고, 서버에서 실패하면 원래대로 되돌리면서 알려줍니다.

## 4. 내년에 다시 쓰기 (인수인계)

Supabase 무료 플랜은 **오래 안 쓰면 프로젝트가 일시정지**됩니다.
1년에 3일만 쓰는 서비스라, **매년 Supabase 프로젝트를 새로 만드는 것을 권장**합니다. 5분이면 됩니다.

### 내년 준비 (5분)

1. Supabase에서 **새 프로젝트** 생성 (1-1번 참고)
2. **SQL Editor** 에 `supabase/schema.sql` 붙여넣고 Run (1-2번 참고)
3. `.env.local` 의 URL / anon key **두 줄만** 새 값으로 교체
4. 배포했다면 Vercel의 Environment Variables 도 같은 값으로 교체 후 **Redeploy**
5. 관리자 비밀번호 변경 → 새 명단 업로드 → FG 계정 업로드

### 넘겨줘야 할 것

- [ ] 이 폴더 전체 (또는 GitHub 저장소 주소)
- [ ] Supabase 가입에 쓴 **학생회 공용 구글 계정** 정보
- [ ] Vercel 계정 정보 (배포했다면)
- [ ] 관리자 아이디 / 비밀번호

> 작년 데이터가 필요하면 **미접수자 화면의 CSV 저장**이나
> Supabase 대시보드의 **Table Editor → participants → Export** 로 미리 백업해두세요.

## 5. 문제가 생겼을 때

| 증상 | 원인 / 해결 |
| --- | --- |
| **"Supabase 연결 설정이 필요합니다"** | `.env.local` 이 없거나 값이 안 채워짐. 만든 뒤 **서버를 껐다 켜야** 합니다 (`Ctrl+C` 후 `npm run dev`) |
| **로그인이 안 됨** | 이름/학번의 앞뒤 공백을 확인하세요. ⚙️ → 계정 탭에서 등록 여부를 확인할 수 있습니다 |
| **FG 화면이 비어 있음** | 담당 LC가 등록되지 않았습니다. ⚙️ → 계정 에서 빨간 '담당 LC 없음' 표시를 확인하세요 |
| **접수했는데 FG 화면에 안 뜸** | 최대 60초 안에 자동으로 맞춰집니다. 급하면 FG 화면의 🔄 버튼을 누르세요 |
| **명단이 다 사라졌다** | '전체 교체'로 업로드했을 가능성이 큽니다. Supabase → Table Editor 에서 확인하세요 |
| **화면이 하얗게만 나옴** | 브라우저에서 F12 → Console 탭의 빨간 글씨를 확인하세요 |
| **행사 당일 사이트가 안 열림** | Supabase 프로젝트가 일시정지됐을 수 있습니다. 대시보드에서 **Restore** 를 누르면 살아납니다. **행사 1주일 전에 미리 확인하세요** |

## 6. 개발자용 정보

### 기술 구성

| | |
| --- | --- |
| 프론트엔드 | React 18 + Vite 7 + Tailwind CSS 4 |
| 데이터베이스 | Supabase (PostgreSQL) |
| 실시간 | Supabase Realtime **Broadcast** |
| 배포 | 정적 사이트 (Vercel / Netlify / Cloudflare Pages) |

### 폴더 구조

```
supabase/schema.sql     데이터베이스 전체 정의 (테이블 + 함수 + 보안)
src/
  lib/
    supabase.js         Supabase 연결
    api.js              서버 함수 호출 (화면 코드는 여기만 씁니다)
    session.js          로그인 유지 (localStorage)
    realtime.js         실시간 방송 송수신
    korean.js           초성 변환
    format.js           연락처/LC/시각 표시
    csv.js              CSV·엑셀 붙여넣기 파싱
    dedupe.js           중복/오류 검사
  components/           버튼·입력창·모달·토스트 등 공용 부품
  hooks/                온라인 감지, 화면 꺼짐 방지
  screens/              화면들
  App.jsx               세션·명단·실시간을 총괄
```

### 보안 설계

- 모든 테이블에 **RLS(Row Level Security)를 켜고 정책은 하나도 만들지 않았습니다.**
  → 브라우저에서 테이블에 직접 접근하는 것이 **전면 차단**됩니다.
- 데이터는 오직 `security definer` 함수(`app_*`)를 통해서만 오갑니다.
- FG에게는 서버가 **담당 LC 인원만 잘라서** 보냅니다.
  → 개발자도구를 열어도 담당하지 않는 LC의 정보는 볼 수 없습니다.
  (담당 LC 안에서는 연락처·학번을 전부 볼 수 있습니다 — 현장에서 연락해야 하므로)
- 실시간 방송에는 개인정보를 싣지 않습니다 (참가자 id / LC / 접수시각만).

### 동시 접수 처리

`app_check_in` 은 `where checked_in_at is null` 조건으로 UPDATE 합니다.
두 창구에서 같은 사람을 동시에 눌러도 한 번만 처리되고, 나중에 누른 쪽에는
"이미 접수되었습니다" 안내가 뜹니다.

### 왜 폴링을 안 쓰나

이전 버전(Google Apps Script)은 15초마다 서버를 호출했습니다.
FG 60명 기준 분당 240회 호출이라 Apps Script의 동시 실행 제한과 일일 실행시간 한도에 걸립니다.
지금은 접수처가 **방송을 한 번 쏘고** 모든 화면이 그걸 받는 방식이라 인원이 늘어도 부담이 없습니다.
방송을 놓쳤을 경우를 대비해 60초마다 한 번씩만 전체를 다시 맞춥니다.
